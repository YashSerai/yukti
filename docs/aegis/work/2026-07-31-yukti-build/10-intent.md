# Yukti Build Intent

## Requested outcome

Build, verify, publish, and prepare Yukti for hackathon submission with a real Prava sandbox lifecycle and consequential Composio, Linq, Senso, and Gemini Flash integration.

## Scope

Execute `docs/aegis/plans/2026-07-31-yukti-hackathon.md` inline. Publish through ChatGPT Sites and use one no-cost backend only if Sites cannot securely host the full contract.

## Non-goals

Production payments, unattended real purchases, Gemini 3.1 Pro, native apps, arbitrary browser checkout automation, NANDA before core stability, and use of the Soulspace Google Cloud project.

## Risk hints

Payment authorization, scoped credential handling, webhook idempotency, personal-data minimization, provider sandbox expiry, model cost, public callback capabilities, and honest fixture labelling.

## Baseline usage

All required local baselines and provider references have been acknowledged and cited. ChatGPT Sites capabilities and the final public callback URLs remain verification outputs, not missing product requirements. Decision: continue.

## Impact statement

The work creates a new web application, relational schema, provider adapters, OAuth and webhook surfaces, deterministic payment authorization, responsive UI, deployment, and submission evidence. All source changes stay inside this project and its isolated implementation worktree.

## Execution readiness

- Intent lock: complete the generalized event-to-action product and polished Sarah demonstration
- Scope fence: approved spec non-goals and cost boundaries
- Baseline lock: approved design, initial baseline, and implementation plan
- Compatibility: Windows, Sites publishing, server-only secrets, single optional backend
- Retirement: fixtures remain test-only and cannot represent connected provider outcomes
- Verification: type, lint, unit, integration, browser, responsive, accessibility, public deployment, secret scan
- Review gates: provider mutation, attended payment, publish, and final evidence audit
